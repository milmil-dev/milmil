---
title: ネットワークの問題
description: 接続、リバースプロキシ、WebSocket の問題のトラブルシューティング。
---

<Accordions>
<Accordion title="ネットワーク上の他のデバイスから milmil にアクセスできない">
**解決方法：**

1. milmil が `127.0.0.1`（localhost のみ）ではなく `0.0.0.0` でリッスンしていることを確認
2. ファイアウォールルールを確認 — ポート 3000（Web）と 8080（API）が開放されている必要があります
3. IP アドレスでアクセスしてみる（例：`http://192.168.1.100:3000`）
4. Docker の場合、`-p 3000:3000 -p 8080:8080` でポートがマッピングされていることを確認
</Accordion>

<Accordion title="リバースプロキシで 502 Bad Gateway">
**一般的な原因：**

1. milmil サービスが実行されていない — `docker ps` で確認
2. プロキシ設定のアップストリームポートが間違っている
3. milmil は HTTP のみを提供しているのにプロキシが HTTPS でアップストリームに接続しようとしている

**解決方法：** サービスが実行中であることを確認してから、プロキシのエラーログ（Nginx の場合は `/var/log/nginx/error.log`）を確認してください。
</Accordion>

<Accordion title="WebSocket 接続が失敗する">
**症状：** 弾幕が読み込まれない、通知がリアルタイムで更新されない。

**解決方法：**

1. リバースプロキシが WebSocket アップグレードヘッダーを転送していることを確認 — [リバースプロキシ](/docs/configuration/reverse-proxy) を参照
2. `/ws` と `/api/` の両方のパスで WebSocket サポートが設定されていることを確認
3. 一部の CDN（Cloudflare 無料プラン）は WebSocket に制限がある場合があります — CDN の設定を確認してください
</Accordion>

<Accordion title="ブラウザコンソールに CORS エラー">
**原因：** API とフロントエンドが異なるドメインまたはポートにあり、適切な CORS ヘッダーがない。

**解決方法：**

1. リバースプロキシを使用してフロントエンドと API を同じドメインで提供する（推奨）
2. 別々に実行する場合、milmil の API は `CORS_ORIGIN` 環境変数に基づいて自動的に CORS ヘッダーを設定します
</Accordion>

<Accordion title="Torrent ダウンロードが開始されない">
**解決方法：**

1. ポート `42069`（または設定した `TORRENT_LISTEN_PORT`）が開放されており、ルーターでポートフォワーディングされていることを確認
2. DHT は初回起動時にブートストラップに時間がかかります — 数分待ってください
3. ISP が BitTorrent トラフィックをブロックしていないか確認
4. Docker の場合、Torrent ポートがマッピングされている必要があります：`-p 42069:42069/tcp -p 42069:42069/udp`
</Accordion>
</Accordions>
