---
title: 掃描問題
description: 排解媒體庫掃描同中繼資料比對問題。
---

<Accordions>
<Accordion title="掃描時偵測唔到檔案">
**常見原因：**

1. **路徑錯誤：** 確保媒體庫路徑同你嘅卷掛載一致。Docker 環境下要用容器內嘅路徑（例如 `/media/anime`，唔係 `/path/on/host/anime`）
2. **權限問題：** milmil 進程必須有媒體目錄嘅讀取權限
3. **副檔名：** milmil 掃描常見嘅影片副檔名（`.mkv`、`.mp4`、`.avi`、`.webm` 等）。非標準嘅副檔名會被跳過
4. **隱藏檔案：** 以 `.` 開頭嘅檔案預設會被忽略
</Accordion>

<Accordion title="動畫比對到錯誤嘅條目">
**解決方法：**

1. 去媒體庫詳情頁
2. 點選比對錯誤嘅動畫條目
3. 點選 **取消比對** 移除錯誤嘅比對
4. 點選 **手動比對** 並搜尋正確嘅動畫
5. 喺搜尋結果中選擇正確嘅條目

<Callout type="info">
提示：DandanPlay 檔案雜湊比對係最準確嘅方法。如果你嘅檔案有標準嘅字幕組命名（例如 `[SubGroup] Title - 01.mkv`），比對準確度會好高。
</Callout>
</Accordion>

<Accordion title="掃描卡住或者好慢">
**常見原因：**

1. **網路儲存延遲：** 掃描遠端後端（SMB、SFTP、rclone）會比本機儲存慢
2. **大型媒體庫：** 首次掃描大型媒體庫（10,000+ 個檔案）可能需要幾分鐘
3. **FFmpeg 探測：** 每個檔案都要探測編解碼器資訊 — 呢個會增加每個檔案嘅處理時間
4. **API 速率限制：** 中繼資料供應商可能會對大量批次比對請求進行速率限制

**解決方法：** 喺 UI 檢查掃描進度。如果真係卡住咗，重啟 milmil 然後試吓先掃描較細嘅子集。
</Accordion>

<Accordion title="Rclone 後端無法連接">
**解決方法：**

1. 獨立驗證你嘅 rclone 遠端係咪正常：`rclone ls remote:path`
2. 檢查 rclone 設定係咪可以畀 milmil 進程存取
3. Docker 環境下要將 rclone 設定掛載入容器
4. 確保雲端供應商嘅憑證未過期（OAuth 權杖需要定期重新整理）
</Accordion>
</Accordions>
