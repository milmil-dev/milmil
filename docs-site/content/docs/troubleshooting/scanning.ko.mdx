---
title: 스캔 문제
description: 라이브러리 스캔 및 메타데이터 매칭 문제를 해결합니다.
---

<Accordions>
<Accordion title="스캔 중 파일이 감지되지 않음">
**일반적인 원인:**

1. **잘못된 경로:** 라이브러리 경로가 볼륨 마운트와 일치하는지 확인하세요. Docker에서는 컨테이너 측 경로를 사용하세요 (예: `/path/on/host/anime`가 아닌 `/media/anime`)
2. **권한:** milmil 프로세스가 미디어 디렉토리에 대한 읽기 접근 권한이 있어야 합니다
3. **파일 확장자:** milmil은 일반적인 비디오 확장자(`.mkv`, `.mp4`, `.avi`, `.webm` 등)를 스캔합니다. 비표준 확장자는 건너뜁니다
4. **숨김 파일:** `.`으로 시작하는 파일은 기본적으로 무시됩니다
</Accordion>

<Accordion title="애니메이션이 잘못된 항목에 매칭됨">
**해결 방법:**

1. 라이브러리 상세 페이지로 이동하세요
2. 잘못 매칭된 애니메이션 항목을 클릭하세요
3. **매칭 해제**를 클릭하여 잘못된 매칭을 제거하세요
4. **수동 매칭**을 클릭하고 올바른 애니메이션을 검색하세요
5. 검색 결과에서 올바른 항목을 선택하세요

<Callout type="info">
팁: DandanPlay 파일 해시 매칭이 가장 정확한 방법입니다. 파일이 표준 자막 그룹 명명 규칙(예: `[SubGroup] Title - 01.mkv`)을 사용하는 경우 매칭 정확도가 높습니다.
</Callout>
</Accordion>

<Accordion title="스캔이 멈추거나 매우 느림">
**일반적인 원인:**

1. **네트워크 스토리지 지연:** 원격 백엔드(SMB, SFTP, rclone) 스캔은 로컬 스토리지보다 느립니다
2. **대규모 라이브러리:** 대규모 라이브러리(10,000개 이상의 파일)의 첫 스캔은 몇 분이 걸릴 수 있습니다
3. **FFmpeg 프로빙:** 각 파일의 코덱 정보를 분석하므로 파일당 시간이 추가됩니다
4. **API 속도 제한:** 대규모 일괄 매칭 시 메타데이터 제공업체가 요청을 속도 제한할 수 있습니다

**해결 방법:** UI에서 스캔 진행 상황을 확인하세요. 정말로 멈춘 경우 milmil을 재시작하고 먼저 작은 하위 세트를 스캔해 보세요.
</Accordion>

<Accordion title="Rclone 백엔드가 연결되지 않음">
**해결 방법:**

1. rclone 리모트가 독립적으로 작동하는지 확인하세요: `rclone ls remote:path`
2. rclone 설정이 milmil 프로세스에 접근 가능한지 확인하세요
3. Docker의 경우 rclone 설정을 컨테이너에 마운트하세요
4. 클라우드 제공업체 자격 증명이 만료되지 않았는지 확인하세요 (OAuth 토큰은 주기적인 갱신이 필요합니다)
</Accordion>
</Accordions>
