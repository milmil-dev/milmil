---
title: 扫描问题
description: 排查媒体库扫描和元数据匹配问题。
---

<Accordions>
<Accordion title="扫描时未检测到文件">
**常见原因：**

1. **路径错误：** 确保媒体库路径与卷挂载一致。在 Docker 中，使用容器内路径（例如 `/media/anime`，而非 `/path/on/host/anime`）
2. **权限问题：** milmil 进程必须对媒体目录有读取权限
3. **文件扩展名：** milmil 扫描常见的视频扩展名（`.mkv`、`.mp4`、`.avi`、`.webm` 等）。非标准扩展名会被跳过
4. **隐藏文件：** 以 `.` 开头的文件默认被忽略
</Accordion>

<Accordion title="动画匹配到了错误的条目">
**解决方案：**

1. 前往媒体库详情页
2. 点击匹配错误的动画条目
3. 点击**取消匹配**以移除错误的匹配
4. 点击**手动匹配**并搜索正确的动画
5. 从搜索结果中选择正确的条目

<Callout type="info">
提示：DandanPlay 文件哈希匹配是最精确的方式。如果你的文件使用标准字幕组命名（例如 `[SubGroup] Title - 01.mkv`），匹配准确率会很高。
</Callout>
</Accordion>

<Accordion title="扫描卡住或非常慢">
**常见原因：**

1. **网络存储延迟：** 扫描远程后端（SMB、SFTP、rclone）比本地存储更慢
2. **大型媒体库：** 首次扫描大型媒体库（10,000+ 文件）可能需要几分钟
3. **FFmpeg 探测：** 每个文件都需要探测编解码器信息 — 这会增加每个文件的处理时间
4. **API 速率限制：** 元数据提供商可能对大批量匹配请求进行速率限制

**解决方案：** 在界面中查看扫描进度。如果确实卡住，重启 milmil 并尝试先扫描较小的子集。
</Accordion>

<Accordion title="Rclone 后端无法连接">
**解决方案：**

1. 验证你的 rclone 远程配置是否独立可用：`rclone ls remote:path`
2. 检查 milmil 进程是否可以访问 rclone 配置文件
3. 在 Docker 中，将你的 rclone 配置挂载到容器内
4. 确保云服务提供商的凭据未过期（OAuth 令牌需要定期刷新）
</Accordion>
</Accordions>
