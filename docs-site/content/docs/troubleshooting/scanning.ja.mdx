---
title: スキャンの問題
description: ライブラリスキャンとメタデータマッチングの問題のトラブルシューティング。
---

<Accordions>
<Accordion title="スキャン中にファイルが検出されない">
**一般的な原因：**

1. **パスが間違っている：** ライブラリパスがボリュームマウントと一致していることを確認してください。Docker ではコンテナ側のパスを使用してください（例：`/path/on/host/anime` ではなく `/media/anime`）
2. **権限：** milmil プロセスがメディアディレクトリへの読み取りアクセス権を持っている必要があります
3. **ファイル拡張子：** milmil は一般的な動画拡張子（`.mkv`、`.mp4`、`.avi`、`.webm` など）をスキャンします。非標準の拡張子はスキップされます
4. **隠しファイル：** `.` で始まるファイルはデフォルトで無視されます
</Accordion>

<Accordion title="アニメが間違ったエントリにマッチングされた">
**解決方法：**

1. ライブラリ詳細ページに移動
2. 誤ってマッチングされたアニメエントリをクリック
3. **マッチ解除** をクリックして誤ったマッチングを削除
4. **手動マッチ** をクリックして正しいアニメを検索
5. 検索結果から正しいエントリを選択

<Callout type="info">
ヒント：DandanPlay のファイルハッシュマッチングが最も正確な方法です。ファイルが標準的なファンサブの命名規則（例：`[SubGroup] Title - 01.mkv`）であれば、マッチング精度は高くなります。
</Callout>
</Accordion>

<Accordion title="スキャンが止まる・非常に遅い">
**一般的な原因：**

1. **ネットワークストレージの遅延：** リモートバックエンド（SMB、SFTP、rclone）のスキャンはローカルストレージより低速です
2. **大規模ライブラリ：** 大規模ライブラリ（10,000 ファイル以上）の初回スキャンには数分かかる場合があります
3. **FFmpeg プロービング：** 各ファイルのコーデック情報がプロービングされるため、ファイルごとに時間がかかります
4. **API レート制限：** メタデータプロバイダーが大量のバッチマッチリクエストをレート制限する場合があります

**解決方法：** UI でスキャンの進捗を確認してください。本当に止まっている場合は、milmil を再起動して、まず小さなサブセットからスキャンを試してください。
</Accordion>

<Accordion title="Rclone バックエンドに接続できない">
**解決方法：**

1. rclone リモートが独立して動作することを確認：`rclone ls remote:path`
2. rclone 設定が milmil プロセスからアクセス可能であることを確認
3. Docker の場合、rclone 設定をコンテナ内にマウント
4. クラウドプロバイダーの認証情報が期限切れになっていないことを確認（OAuth トークンは定期的な更新が必要です）
</Accordion>
</Accordions>
