---
title: 掃描問題
description: 排解媒體庫掃描和中繼資料比對問題。
---

<Accordions>
<Accordion title="掃描時未偵測到檔案">
**常見原因：**

1. **路徑錯誤：** 確保媒體庫路徑與磁碟區掛載一致。在 Docker 中，使用容器內的路徑（例如 `/media/anime`，而非 `/path/on/host/anime`）
2. **權限問題：** milmil 程序必須擁有媒體目錄的讀取權限
3. **副檔名：** milmil 會掃描常見的影片副檔名（`.mkv`、`.mp4`、`.avi`、`.webm` 等）。非標準副檔名會被略過
4. **隱藏檔案：** 以 `.` 開頭的檔案預設會被忽略
</Accordion>

<Accordion title="動畫比對到錯誤的條目">
**解決方案：**

1. 前往媒體庫詳情頁
2. 點擊比對錯誤的動畫條目
3. 點擊 **取消比對** 移除錯誤的比對
4. 點擊 **手動比對** 並搜尋正確的動畫
5. 從搜尋結果中選擇正確的條目

<Callout type="info">
提示：DandanPlay 檔案雜湊比對是最精確的方法。如果你的檔案使用標準的字幕組命名格式（例如 `[SubGroup] Title - 01.mkv`），比對準確度會很高。
</Callout>
</Accordion>

<Accordion title="掃描卡住或非常慢">
**常見原因：**

1. **網路儲存延遲：** 掃描遠端後端（SMB、SFTP、rclone）比本機儲存慢
2. **大型媒體庫：** 首次掃描大型媒體庫（10,000+ 個檔案）可能需要數分鐘
3. **FFmpeg 探測：** 每個檔案都需要探測編解碼器資訊 — 這會增加每個檔案的處理時間
4. **API 速率限制：** 中繼資料提供商可能會對大批量比對請求進行速率限制

**解決方案：** 在 UI 中查看掃描進度。如果確實卡住了，重新啟動 milmil 並先嘗試掃描較小的子集。
</Accordion>

<Accordion title="Rclone 後端無法連線">
**解決方案：**

1. 先獨立驗證你的 rclone 遠端是否正常運作：`rclone ls remote:path`
2. 確認 rclone 設定檔可被 milmil 程序存取
3. 若使用 Docker，需將 rclone 設定檔掛載到容器中
4. 確認雲端服務提供商的憑證未過期（OAuth 權杖需要定期重新整理）
</Accordion>
</Accordions>
