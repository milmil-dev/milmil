## 시스템 개요

milmil은 셀프 호스팅 배포를 위해 설계된, 모놀리식 Go 백엔드와 React SPA 프론트엔드로 구성됩니다.

```
┌─────────────────────────────────────────────────┐
│                   Clients                       │
│         Browser (PWA)  │  Telegram/Discord Bot  │
└───────────┬─────────────────────┬───────────────┘
            │ HTTP/WS             │ Bot API
┌───────────▼─────────────────────▼───────────────┐
│                milmil-api (Go)                  │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────┐│
│  │ REST API │ │WebSocket │ │ Bot Engine       ││
│  └────┬─────┘ └────┬─────┘ └───────┬──────────┘│
│       │             │               │           │
│  ┌────▼─────────────▼───────────────▼──────────┐│
│  │              Service Layer                  ││
│  │  Library │ Stream │ Download │ Discover     ││
│  │  Collection │ Auth │ Notification           ││
│  └────┬────────────────────────────────────────┘│
│       │                                         │
│  ┌────▼────────────────────────────────────────┐│
│  │           Infrastructure Layer              ││
│  │  PostgreSQL/SQLite │ Redis │ FFmpeg │ Rclone││
│  └─────────────────────────────────────────────┘│
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│              milmil-web (React SPA)             │
│  Served via Nginx or dev server                 │
└─────────────────────────────────────────────────┘
```

## 컴포넌트 개요

| 컴포넌트 | 설명 |
|---|---|
| **REST API** | Echo 라우터를 사용한 JSON 엔드포인트. 인증, CRUD, 스트리밍, 검색을 처리합니다. |
| **WebSocket** | 탄막(danmaku), 알림, 스캔 진행 상황을 위한 실시간 이벤트 푸시. |
| **Bot Engine** | Telegram 및 Discord 어댑터를 갖춘 플랫폼 독립적 봇. |
| **Service Layer** | 라이브러리 스캔, 메타데이터 매칭, 다운로드 관리, 컬렉션 동기화를 위한 비즈니스 로직. |
| **FFmpeg** | 미디어 프로빙, 컨테이너 리먹싱, HLS 트랜스코딩. |
| **Rclone** | 40개 이상의 제공업체를 지원하는 클라우드 스토리지 추상화. |

## 데이터 흐름: 라이브러리 스캔

<Steps>
<Step>
### 파일 검색

스토리지 백엔드(로컬, SMB, rclone 등)를 탐색하여 모든 미디어 파일을 열거합니다.
</Step>
<Step>
### 미디어 프로빙

FFmpeg가 각 파일의 코덱 정보, 해상도, 재생 시간, 내장 자막 및 오디오 트랙을 분석합니다.
</Step>
<Step>
### 메타데이터 매칭

제공업체 파이프라인을 통해 파일을 애니메이션 항목에 매칭합니다: DandanPlay (해시) → Bangumi (제목) → AniList (제목) → TMDB (폴백).
</Step>
<Step>
### 보강

매칭된 제공업체에서 커버 이미지, 에피소드 제목, 설명, 평점을 가져옵니다.
</Step>
<Step>
### 저장

모든 메타데이터를 데이터베이스에 저장합니다. 스캔 완료 알림을 전송합니다.
</Step>
</Steps>

## 데이터 흐름: 스트리밍

```
Client request
    │
    ▼
┌─────────────────┐
│ Codec supported? │──yes──▶ Direct Play (byte-range)
└────────┬────────┘
         │ no
         ▼
┌─────────────────┐
│ Container only?  │──yes──▶ Remux (MKV→MP4, no re-encode)
└────────┬────────┘
         │ no
         ▼
    HLS Transcode (FFmpeg)
```

## 기술 스택

| 기술 | 설명 |
|---|---|
| **백엔드** | Go — Chi 라우터, sqlc, golang-migrate, anacrolix/torrent |
| **프론트엔드** | React — Vite, TanStack Router, TanStack Query, Tailwind CSS |
| **데이터베이스** | PostgreSQL/SQLite — golang-migrate로 스키마 관리 |
| **캐시** | Redis — 선택 사항, 인메모리 폴백 가능 |
| **미디어** | FFmpeg — 프로빙, 리먹싱, HLS 트랜스코딩 |
| **스토리지** | Rclone — 40개 이상의 클라우드 제공업체 백엔드 |
| **문서** | Fumadocs — i18n을 지원하는 Next.js 기반 문서 사이트 |
