## 概要

milmil のライブラリシステムでは、複数のストレージバックエンドからアニメファイルを整理・管理できます。ファイルは自動的にスキャンされ、識別され、Bangumi、AniList、DandanPlay のメタデータを使用してアニメエントリにマッチングされます。

## ストレージバックエンド

| バックエンド | 説明 |
|---------|-------------|
| **ローカル** | ホストファイルシステム上のディレクトリ |
| **SMB/CIFS** | Windows ネットワーク共有 |
| **SFTP** | SSH ファイル転送 |
| **FTP** | 標準 FTP |
| **WebDAV** | クラウドストレージ（Nextcloud など） |
| **HTTP** | ダイレクト HTTP ファイルアクセス |
| **Rclone** | 40 以上のクラウドプロバイダー（Google Drive、OneDrive、Dropbox、S3 など） |

## スキャン

ライブラリをスキャンすると、milmil は：

1. ディレクトリツリーを走査してメディアファイルを検出
2. FFmpeg でメタデータを抽出（コーデック、解像度、再生時間、字幕）
3. 複数のプロバイダーを使用してファイルをアニメエントリにマッチング
4. エピソードにカバー画像、タイトル、あらすじを付加

スキャンは手動でトリガーするか、自動実行に設定できます。

## メタデータマッチング

milmil はマルチプロバイダーマッチングパイプラインを使用します：

1. **DandanPlay ハッシュ** — 最も正確、ファイルハッシュでマッチング
2. **Bangumi** — Bangumi データベースに対するタイトルベースマッチング
3. **AniList** — 代替タイトルマッチング
4. **TMDB** — フォールバッククロスリファレンス

マッチしなかったファイルはライブラリ詳細ページから手動でマッチングできます。

## ファイルブラウザ

ライブラリ詳細ページにはファイルブラウザがあり、以下を表示します：

- ファイル数付きディレクトリツリー
- メディアファイル詳細（コーデック、解像度、サイズ）
- 各ファイルのマッチ状態
- 一括マッチ/マッチ解除操作
