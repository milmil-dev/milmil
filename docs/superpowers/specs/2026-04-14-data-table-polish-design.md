# Data-Table Polish Design

**Date:** 2026-04-14
**Scope:** Server-side sorting + batch selection for the library media files table

## Context

The `FileTable` component in `LibraryDetailPage.tsx` displays media files with server-side pagination via TanStack Query. It uses `MotionTable` (a generic TanStack React Table wrapper) with fixed column widths and `getCoreRowModel()` only.

Missing features: column sorting, batch file selection with bulk match/unmatch operations.

## 1. Server-Side Sorting

### API Changes

Add two query parameters to `GET /api/v1/libraries/:id/media-files`:

| Param | Type | Default | Allowed Values |
|-------|------|---------|----------------|
| `sort_by` | string | `filename` | `filename`, `size_bytes`, `match_status`, `subtitle_count` |
| `sort_order` | string | `asc` | `asc`, `desc` |

Validate `sort_by` against a whitelist. Invalid values fall back to defaults.

### SQL Changes

The `ListMediaFiles` query in `queries/media_files.sql` currently has a fixed `ORDER BY`. Replace with dynamic ordering based on the validated `sort_by` and `sort_order` params. Since sqlc doesn't support dynamic ORDER BY, use a CASE-based approach or build the query in Go with whitelist validation.

### Frontend Changes

**Sorting state:** Add `sortBy` and `sortOrder` to the `FileTable` component state. Pass as query params to the API call. Reset page to 1 on sort change.

**MotionTable header:** Make headers clickable when the column is sortable. Clicking toggles: `asc` -> `desc` -> clear (back to default). Show a sort direction indicator (chevron up/down) next to the active sort column.

**Sortable columns:** `filename`, `size_bytes`, `match_status`, `subtitle_count`. The `matched` (anime title) and `actions` columns are not sortable.

## 2. Batch Selection

### Checkbox Column

Add a checkbox column as the first column in the table:

- **Header checkbox:** Toggles select/deselect all rows on the current page
- **Row checkbox:** Toggles individual row selection
- **Visual:** Subtle white/opacity checkbox matching the existing design language (no accent color borders per project convention)

Use TanStack Table's built-in `getRowId` (set to `row.original.id`) and row selection model (`getRowSelectionModel()`).

### Selection State

- `rowSelection` state (`Record<string, boolean>`) managed in `FileTable`
- Clear selection on page change, filter change, or search change
- Selection is page-scoped (no cross-page selection)

### Floating Action Bar

When `selectedCount > 0`, render a fixed-position bar at the bottom center of the viewport:

```
┌─────────────────────────────────────────────────┐
│  ☑ 5 selected    [Bulk Match]    [Bulk Unmatch] │
└─────────────────────────────────────────────────┘
```

- Animate in/out with Motion (slide up + fade)
- `bg-white/[0.08] backdrop-blur` styling, rounded, with shadow
- **Bulk Match** button: opens the existing match dialog. Applies the selected anime+episode to all selected unmatched files, assigning sequential episode numbers starting from the specified episode.
- **Bulk Unmatch** button: shows confirmation dialog, then clears match for all selected matched files.

### New API Endpoints

**`POST /api/v1/media-files/bulk-match`**

Request:
```json
{
  "file_ids": ["uuid1", "uuid2", "uuid3"],
  "bangumi_id": 12345,
  "episode_start": 1
}
```

Assigns sequential episodes starting from `episode_start` to the files in the order they appear in `file_ids`. Returns 200 with count of matched files.

**`POST /api/v1/media-files/bulk-unmatch`**

Request:
```json
{
  "file_ids": ["uuid1", "uuid2", "uuid3"]
}
```

Clears match data for the specified files. Returns 200 with count of unmatched files.

Both endpoints require authentication and validate that all file IDs belong to the same library.
